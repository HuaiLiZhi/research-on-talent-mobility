# OpenAlex 数据清洗、提取与科研人员流动事件构造说明

## 1. 文档范围

本文档根据项目根目录中的 OpenAlex 处理代码整理，说明 OpenAlex 数据从快照提取、版本去重、年度机构位置构造，到城市流动事件和学科分类的完整处理口径。

本文档**不以 `sci-mobility-emb-master` 目录中的原项目代码作为 OpenAlex 清洗依据**。不过，根目录中的 `prepare_sci_mobility_inputs.py` 会把 OpenAlex 数据转换为该项目所需的输入格式，因此本文会将其作为一条独立的“桥接流程”说明，并明确区分它与城市流动主流程的不同口径。

涉及的主要文件如下：

| 文件 | 作用 |
|---|---|
| `extract_openalex_mobility_to_csv.py` | 从 OpenAlex 作者和机构快照提取轻量级流动数据表 |
| `dedupe_openalex_mobility_csv.py` | 按最新 `updated_date` 对作者、机构及作者子表进行版本去重 |
| `analyze_city_mobility.py` | 从作者年度位置构造城市流动事件，并按学科层级聚合 |
| `clean_city_mobility_regions.py` | 补充缺失地区字段，并合并重复的 OD—年份—学科记录 |
| `prepare_sci_mobility_inputs.py` | 将 OpenAlex 年度机构记录转换为旧流动项目的输入格式 |
| `analyze_flow_symmetry.py` | 从桥接后的职业轨迹构造有向流动，并测试流动对称性 |
| `extract_openalex_to_csv.py` | 通用 OpenAlex 实体提取程序，可拆分 works、authorships、机构和国家等关系表 |

---

## 2. OpenAlex 数据处理链

### 2.1 数据来源

流动主流程直接读取 OpenAlex snapshot 中的两个实体：

- `authors`
- `institutions`

作者流动履历主要来自作者实体中的：

- `id`
- `display_name`
- `orcid`
- `affiliations`
- 每条 affiliation 对应的 `years`
- `topics`
- `topic_share`
- `works_count`
- `cited_by_count`
- `summary_stats`

机构地理信息来自机构实体中的：

- `id`
- `ror`
- `display_name`
- `type`
- `country_code`
- `geo.city`
- `geo.region`
- `geo.country_code`
- `geo.country`
- `geo.latitude`
- `geo.longitude`

因此，城市流动主流程并不是根据每篇论文的发表日期和 `works.authorships` 重新构造职业履历，而是直接使用 OpenAlex 已整理到作者实体中的年度 affiliation history。

### 2.2 原始表提取

`extract_openalex_mobility_to_csv.py` 生成以下表：

| 输出表 | 内容 |
|---|---|
| `detail_authors.csv` | 作者基本信息及统计指标 |
| `authors__topics.csv` | 作者主题及对应 domain、field、subfield |
| `authors__topic_share.csv` | 作者主题份额及对应学科层级 |
| `authors__affiliations.csv` | 作者的机构 affiliation 列表 |
| `authors__affiliation_years.csv` | 每条 affiliation 对应的年份 |
| `institutions.csv` | 机构基本信息和地理坐标 |
| `detail_author_year_locations.csv` | 作者—年份—机构—城市—地区—国家位置表 |

提取时会遍历作者的全部 affiliations，并进一步遍历每条 affiliation 的全部年份。每个“作者—affiliation—年份”组合都会写入一条 `detail_author_year_locations.csv` 记录。

机构 ID 会与 `institutions` 实体匹配，以补充城市、地区、国家和经纬度。若机构 ID 无法匹配，部分地理字段可能为空，但代码仍可能保留该作者—年份—机构记录。

### 2.3 Snapshot 版本去重

OpenAlex snapshot 的多个 `updated_date` 分区中可能存在同一个作者或机构的多个版本。`dedupe_openalex_mobility_csv.py` 执行以下去重：

1. 对每个作者 ID 找到最大的 `updated_date`；
2. `detail_authors.csv` 中每个作者只保留该日期的一条实体记录；
3. 作者的 topics、topic share、affiliations、affiliation years 和 year locations 只保留与作者最新日期一致的记录；
4. 对每个机构 ID 同样只保留最新版本。

这一步是**实体版本去重**，不是作者消歧，也不是流动事件去重。

### 2.4 年度代表位置选择

`detail_author_year_locations.csv` 可以包含同一作者、同一年、多个机构的记录。`analyze_city_mobility.py` 在构造城市轨迹时为每个作者建立：

```text
year -> (affiliation_position, location)
```

如果同一年出现多个 affiliation，只保留 `affiliation_position` 最小的一条。因此，城市流动主流程将每位作者每年压缩为一个代表位置。

### 2.5 流动事件构造

对每位作者：

1. 将年度代表位置按年份升序排列；
2. 比较相邻的两个可观测年份；
3. 若城市名称不同，则判定发生流动；
4. 若城市名称相同，但两边国家代码均存在且国家代码不同，也判定发生流动；
5. 事件年份记为目的地位置对应的年份；
6. 起点或终点城市名为空时，不生成该次事件。

需要注意，相邻观测年份不一定是连续自然年。例如只有 2015 年和 2019 年记录时，代码仍会直接比较这两个位置，并把变化记为 2019 年的流动事件。

### 2.6 流动聚合

原始事件随后分别按以下四个学科层级聚合：

- domain
- field
- subfield
- topic

聚合键包括：

- 起点城市和国家代码；
- 终点城市和国家代码；
- 事件年份；
- 对应层级的学科标签。

输出文件为：

- `city_mobility_by_domain.csv`
- `city_mobility_by_field.csv`
- `city_mobility_by_subfield.csv`
- `city_mobility_by_topic.csv`

### 2.7 地区补全与再次合并

`clean_city_mobility_regions.py` 对上述聚合结果进行进一步清理：

1. 对缺失的 `region`，寻找国家、城市名、纬度和经度均相同的其他记录；
2. 如果匹配记录只有一个无冲突的地区值，则进行补充；
3. 如果同一城市键对应多个冲突地区，则保持缺失，不强行选择；
4. 补全后，对起点、终点、年份、学科标签等字段完全相同的记录合并，并对 `mobility_count` 求和。

## 3. 同时拥有多国机构署名的处理

### 3.1 原始提取阶段

原始提取阶段会保留同一作者同一年中的所有机构。若某位作者在同一年同时署名中国机构和美国机构，`detail_author_year_locations.csv` 原则上会包含两条作者—年份—机构记录。

提取阶段没有执行：

- 按机构分数计数；
- 按论文数量确定主机构；
- 通讯作者机构优先；
- 第一作者机构优先；
- 本国机构优先；
- 将同年多国署名直接判断为国际迁移。

### 3.2 城市流动主流程

`analyze_city_mobility.py` 对同一作者—年份只保留 `affiliation_position` 最小的机构。因此，同年多机构或多国机构最终只会有一个位置进入城市迁移轨迹。

例如：

| 年份 | affiliation position | 机构国家 | 主流程处理 |
|---|---:|---|---|
| 2019 | 1 | 中国 | 保留 |
| 2019 | 2 | 美国 | 丢弃，不进入该年轨迹 |

因此：

- 不会把同年中国和美国同时作为两个所在地；
- 不会仅因同年多国署名生成国际流动事件；
- 第二及后续 affiliation 不参与该作者当年的城市迁移判断；
- 结果依赖 OpenAlex affiliation 数组的排序。

这里的 `affiliation_position` 是代码枚举 OpenAlex affiliation 列表得到的位置，不是项目根据任职主次、论文数量或可信度计算出的主机构排名。

### 3.3 桥接流程的不同口径

`prepare_sci_mobility_inputs.py` 使用以下键去重：

```text
(author_id, year, institution_id, field)
```

因此，同一作者同一年不同机构都会保留。该流程与城市流动主流程不同：

| 流程 | 同年多机构处理 |
|---|---|
| `analyze_city_mobility.py` | 只保留 affiliation position 最小的一个机构 |
| `prepare_sci_mobility_inputs.py` | 保留所有不同机构，仅去除完全相同的作者—年份—机构记录 |

两条流程生成的数据不能视为同一流动口径。

## 4. 同一年多次变动的处理

### 4.1 主流程不能识别同年内顺序

OpenAlex 作者 affiliation history 在本项目中只提供“某机构对应哪些年份”，没有月、日或同年机构之间的先后顺序。

城市流动主流程又将同一作者—年份压缩为一个代表机构，因此不能恢复同年内的：

```text
A -> B -> C
```

等变化顺序。

同一年无论出现多少机构，城市流动主流程最多保留一个年度位置。

### 4.2 跨年事件的计数

主流程比较相邻的可观测年份。例如：

| 年份 | 观测机构位置 |
|---|---|
| 2018 | 北京 |
| 2019 | 纽约、伦敦 |
| 2020 | 巴黎 |

若 2019 年纽约的 affiliation position 最小，则轨迹会被压缩为：

```text
北京（2018） -> 纽约（2019） -> 巴黎（2020）
```

最终生成：

- 北京 → 纽约，记在 2019 年；
- 纽约 → 巴黎，记在 2020 年。

2019 年内部可能存在的纽约 → 伦敦无法识别。

### 4.3 同年多机构的方向性检验口径

在桥接数据的方向性检验中，`analyze_flow_symmetry.py` 提供两个选项：

- `--same-year skip`：默认设置，不在同年机构之间构造流动边；
- `--same-year undirected`：将同年所有不同机构两两连接，并同时增加两个方向。

这是因为同年多机构没有可靠的时间先后关系，不能直接解释为确定的有向迁移。

## 5. 回流和重复流动的处理

### 5.1 回流没有单独分类

城市流动主流程没有维护以下标签：

- 是否返回第一次观测的机构；
- 是否返回曾经工作过的机构；
- 是否返回原城市；
- 是否返回原国家；
- 是否为首次迁移、再次迁移或回流。

因此，回流只会作为普通的相邻位置变化计数。

例如：

```text
A（2015） -> B（2016） -> A（2018）
```

会生成两条事件：

1. A → B，记在 2016 年；
2. B → A，记在 2018 年。

第二条可以在研究解释中被视为回流，但当前输出不会将其标记为 `return_migration`。

### 5.2 重复流动会重复计数

例如：

```text
A -> B -> A -> B
```

会生成：

- A → B；
- B → A；
- A → B。

项目没有设置“每位作者整个职业生涯中同一 OD 只能计一次”的限制。不同年份发生的同一方向流动会分别保留；同一 OD—年份—学科下的多个事件则在聚合阶段累加为 `mobility_count`。

### 5.3 连续相同地点不计为流动

例如：

```text
A（2015） -> A（2016） -> B（2017）
```

只会生成 A → B 一条事件。

### 5.4 同城跨机构不计为城市流动

城市流动主流程判断的是城市或国家是否改变，而不是机构 ID 是否改变。因此：

- 北京大学 → 清华大学：不计为城市流动；
- 同一城市内其他机构变动：不计；
- 同名城市但国家代码不同：计为流动；
- 返回同一城市但进入不同机构：在城市层级上不构成回流事件。

### 5.5 回流定义的限制

当前数据不能自动区分：

- 返回原机构；
- 返回原城市但进入其他机构；
- 返回原国家但进入其他城市；
- OpenAlex 漏失中间年份造成的表面回流；
- 作者错误合并造成的异常往返。

如果论文需要报告回流率，应首先明确回流层级，例如：

- 返回曾任机构；
- 返回曾居城市；
- 返回首次观测国家；
- 返回任一历史国家。

当前代码尚未实现这些回流定义。

## 6. 作者消歧及其误差

### 6.1 当前项目的处理

项目直接使用 OpenAlex `author_id` 作为唯一作者标识，没有在项目内部重新进行作者消歧。

虽然数据中保存了 ORCID，但 ORCID 目前只是随行元数据，没有用于：

- 合并相同 ORCID 对应的多个 OpenAlex author ID；
- 拆分具有冲突 ORCID 的 author ID；
- 限制样本只包含有 ORCID 的作者；
- 对有无 ORCID 的样本分别估计流动；
- 校正 OpenAlex 作者聚类。

### 6.2 项目无法给出消歧错误率

仓库中没有发现以下验证：

- 作者消歧人工标注集；
- precision、recall 或 F1；
- pairwise 或 B-cubed 聚类指标；
- 与 ORCID、Scopus、Web of Science 等外部作者标识的系统比对；
- false merge 和 false split 的估计；
- 消歧误差对流动结果的敏感性分析。

因此，不能根据当前项目声称作者消歧错误率为某个确定数值，也不能声称误差可以忽略。

### 6.3 错误合并的影响

如果两个不同作者被 OpenAlex 错误合并为一个 author ID，可能形成虚假的跨地区轨迹。例如两个同名作者分别在中国和美国工作，错误合并后可能被识别为中国 → 美国迁移。

错误合并可能：

- 高估流动人数和事件数；
- 高估长距离与跨国流动；
- 制造不合理的快速往返；
- 造成同一作者学科标签混杂；
- 对常见姓名作者产生更大影响。

### 6.4 错误拆分的影响

如果同一个真实作者被拆成多个 OpenAlex author ID，其职业轨迹会被截断。

错误拆分可能：

- 漏掉跨 author ID 边界的迁移；
- 低估总流动率；
- 低估回流和重复流动；
- 将一个移动作者错误识别为多个不移动或短职业作者。

### 6.5 建议的误差验证

若论文需要讨论消歧误差大小，建议补充以下分析。

#### ORCID 一致性检查

- 检查同一 ORCID 是否对应多个 OpenAlex author ID；
- 检查一个 OpenAlex author ID 是否出现冲突 ORCID；
- 比较有 ORCID 子样本与全样本的流动率和距离分布。

#### 异常轨迹诊断

- 同一作者同年覆盖多个远距离国家；
- 相邻年份跨多个大陆高频往返；
- 同年机构数异常高；
- 学科跨度异常大；
- 单个作者关联论文数、机构数或国家数异常高。

#### 人工标注

分层抽取以下作者进行人工回查：

- 常见姓名与罕见姓名；
- 有 ORCID 与无 ORCID；
- 高流动与低流动；
- 单一学科与跨学科；
- 同年单机构与同年多机构。

随后估计 false merge、false split 或 pairwise precision/recall。

#### 敏感性分析

可比较以下样本的结果：

- 全部作者；
- 仅有 ORCID 的作者；
- 排除同年多国机构的作者；
- 排除异常高速往返轨迹的作者；
- 排除机构或国家数量异常高的作者。

在没有上述验证时，推荐采用以下论文表述：

> 本研究继承 OpenAlex 的作者消歧结果，未在项目内独立估计其误差率。作者错误合并可能高估流动，而错误拆分可能低估流动。

## 7. 学科归属和重复计数

### 7.1 同一层级内只归入一个主学科

`analyze_city_mobility.py` 读取作者 `topics` 中 `position == 1` 的最高排序主题，并同时获得该主题对应的：

- domain；
- field；
- subfield；
- topic。

因此，在同一个学科层级结果表中，一个事件只归入一个类别。例如在 `city_mobility_by_field.csv` 中，一个流动事件不会同时计入两个 field。

缺少分类的作者会被归入 `Unknown`，而不是被分配到多个学科。

### 7.2 同一事件会出现在四个层级文件中

同一个真实流动事件会分别进入：

- 一个 domain；
- 一个 field；
- 一个 subfield；
- 一个 topic。

因此，该事件会在四个不同层级文件中各出现一次。这是同一分类路径在不同层级上的表示，不是同级多学科计数。

但是，如果将四个层级文件直接拼接后求总流动量，会导致对同一事件重复计数。

### 7.3 学科是作者级固定标签

学科分类来自作者整体的最高排序 OpenAlex topic，不是：

- 迁移发生年份的论文主题；
- 迁移前或迁移后的学科；
- 单篇论文的多学科分类；
- 事件级动态学科分类。

因此，一位作者职业生涯内的全部流动事件都会继承同一套作者主学科标签。这种处理测量的是“按作者主学科划分的流动”，不能捕捉作者职业生涯中的学科转换。

### 7.4 桥接流程的学科选择

`prepare_sci_mobility_inputs.py` 可以从 `topic_share` 或 `topics` 中选择分类，并根据 `topic_value` 或 `topic_count` 选出权重最大的一个类别；并列时使用 position 等信息进行排序。

因此，桥接流程同样是单一主学科分类，而不是多学科分数计数。

## 8. 关键口径汇总

| 问题 | 城市流动主流程的实际处理 |
|---|---|
| 同年多机构或多国署名 | 只保留 `affiliation_position` 最小的一个机构 |
| 同年多次变动 | 无法识别先后顺序；每年最多保留一个位置 |
| 跨年变化 | 比较相邻可观测年份，不要求年份连续 |
| 事件年份 | 使用目的地所在年份 |
| 同城跨机构 | 不计为城市流动 |
| 同名城市跨国 | 国家代码不同则计为流动 |
| 回流 | 作为普通反向流动事件，不单独标记 |
| 重复 A → B | 每次相邻观测发生都会计数，不做职业生涯级唯一化 |
| Snapshot 重复版本 | 每个作者或机构保留最新 `updated_date` 版本 |
| 作者消歧 | 完全继承 OpenAlex author ID，项目内无误差率估计 |
| ORCID | 仅作为元数据保存，未用于消歧修正 |
| 同一层级的多学科 | 不会；每个作者只使用一个主分类路径 |
| 四个学科层级 | 同一事件分别进入 domain、field、subfield、topic 文件 |
| 学科时间变化 | 不处理；作者所有事件使用固定主学科 |
| 缺失省份 | 用同国家、城市和经纬度的无冲突记录补充 |
| 缺失城市 | 无法参与城市变化判定 |
| 缺失经纬度 | 城市事件构造不强制排除；桥接流程默认排除无坐标机构 |

## 9. 推荐的方法描述

如果需要在论文方法部分简要描述当前城市流动数据，可采用以下表述：

> 本研究从 OpenAlex 作者与机构快照中提取作者年度机构履历，并按实体的最新更新时间去除快照中的历史版本。机构 ID 与 OpenAlex 机构地理信息匹配，以获得城市、地区、国家及经纬度。对于同一作者同一年存在多个机构的情况，选取 OpenAlex affiliation 列表中位置最靠前的机构作为该年的代表位置。随后按年份排列每位作者的可观测位置，并比较相邻观测年份；当城市发生变化，或同名城市对应的国家代码发生变化时，记录一条流动事件，事件年份定义为目的地位置的年份。相邻观测年份不要求连续。同城机构转换不计为城市流动，回流和重复流动按每次相邻位置变化分别计数。每位作者按照 OpenAlex 排名最高的主题被赋予唯一的 domain、field、subfield 和 topic 分类路径，职业生涯内的所有流动事件使用同一作者主学科标签。作者身份直接采用 OpenAlex author ID，本研究未在项目内重新进行作者消歧。

---

## 10. 方法学限制与建议

当前流程最需要注意的限制包括：

1. **同年多机构选择偏差**：只保留 affiliation position 最小的机构，可能忽略真实的跨国联合任职或同年迁移；
2. **时间精度有限**：数据为年度粒度，无法识别同年内的流动顺序；
3. **非连续年份比较**：跨多个缺失年份的位置变化仍被视为一次迁移；
4. **回流未分类**：返回原机构、原城市和原国家没有被区分；
5. **作者消歧误差未知**：错误合并可能高估流动，错误拆分可能低估流动；
6. **学科为作者级固定标签**：无法反映迁移前后或职业生涯中的学科转换；
7. **多层级文件不可直接合计**：同一事件会在 domain、field、subfield 和 topic 文件中分别出现。

建议至少开展以下稳健性检验：

- 将同年多机构作者排除后重新计算；
- 仅使用有 ORCID 的作者重新计算；
- 分别采用“主机构”“全部机构但跳过同年边”等口径比较结果；
- 限制为连续年份观测后重新计算；
- 排除异常高频跨国往返作者；
- 将返回机构、返回城市和返回国家分别定义为不同回流指标；
- 比较作者固定主学科与事件年份论文主学科的结果差异。
